## What I wanted to learn

MapReduce looks simple when presented as a programming model. The implementation details are where the real lessons live: how work gets partitioned, how failed tasks are replayed, and why data locality matters once scale appears.

## Main takeaways

- The scheduler is where a large part of system behavior becomes visible.
- Simple retry rules become expensive if task bookkeeping is weak.
- Good intermediate file conventions make the overall system easier to reason about.

## Where I would take it next

The next iteration would add clearer worker heartbeats and more realistic handling of stragglers so I can compare coordinator behavior under skewed workloads.
